# 3～5 分钟视频脚本

目标时长：4 分钟左右。语速平稳，画面只保留产品和必要的查询依据，不展示终端密钥或本机绝对路径。

## 0:00～0:25 开场

画面：README 首屏和产品截图。

讲解：

> 这是我独立完成并开源的 ChatBI V2。它不是只把自然语言翻译成 SQL，而是把数据源、语义层、只读 SQL、结果值校验、图表洞察、答案看板和评测做成一个可验证闭环。V1.3.0 已冻结为正式开源 Release，这段视频演示的是发布后的本地求职 Demo。

## 0:25～0:45 功能 1：登录与 Chat-first

画面：登录，再进入“问数据”。

> 登录后默认进入问数据，而不是系统管理后台。业务用户直接用自然语言开始分析，技术细节默认折叠。

## 0:45～1:10 功能 2：数据源与 Schema

画面：数据源列表 → PostgreSQL 详情 → Schema。

> 主验证路径使用本机 PostgreSQL，MySQL 用于第二方言兼容。浏览器只调用 Backend API，数据库账号是只读最小权限，前端不会持有数据库凭据。

## 1:10～1:35 功能 3：语义模型

画面：语义模型列表和编辑器。

> 语义层统一收入、利润、订单量等指标，管理维度、实体、关系、业务术语和同义词。NL2SQL 不是只看裸 Schema，而是在发布版本和口径约束下生成计划。

## 1:35～2:35 功能 4：可验证问数

输入：`2026年按地区按月统计已支付订单收入趋势`。

画面：Streaming 阶段 → 结论 → KPI → 图表 → 洞察 → 明细。

> 这个问题依次经过 Context、NL2SQL、SQLGlot AST Guard、只读 Query Executor 和 Result Oracle。Oracle 会检查指标、维度、时间、过滤、Join 和结果值，而不是因为 HTTP 200 或 SQL 能运行就判定正确。回答固定为业务结论优先，再给 KPI、图表、洞察、明细和推荐追问。

## 2:35～3:00 功能 5：查询依据与安全

画面：打开依据抽屉，再展示安全评测中的 DELETE 拒绝结果。

> 查询依据保留语义口径、SQL、数据源、模型版本、耗时、Oracle 和结果签名。所有生成 SQL 只允许单条 SELECT 或 WITH SELECT；DDL、DML、多语句和危险函数会在访问数据库前失败关闭。

## 3:00～3:25 功能 6：受控 RAG / Multi-Agent

画面：知识问题的引用和 Complex Analysis 公开阶段 Trace。

> 专业知识走 Workspace ACL 和 Citation Guard；复杂分析只允许固定五角色、六个工具、8 步、12 次工具和 30 秒预算。Agent 不能直连数据库，也不能绕过 SQL Guard 和 Result Oracle。

## 3:25～3:55 功能 7：答案、看板、评测

画面：保存答案 → 看板卡片 → 评测中心。

> 验证通过的结果可以保存为版本化答案，再加入看板。评测中心用冻结 Golden Set 对 SQL、结果值、语义和安全边界做回归，形成从一次问数到持续优化的产品闭环。

## 3:55～4:10 结束

> 这个项目最核心的工程价值是：把模型的不确定输出放进确定性的语义、安全、执行和验证边界里，并把每个结论变成可追溯的产品资源。代码、架构、Release 和完整演示材料都在 GitHub。
